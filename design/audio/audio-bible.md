## 1. 音频方向（Audio Direction）

### 1.1 总体基调
治愈 / 女性向 / 「被陪伴的安心感」。一句话：**低操作、高安抚、慢节奏、可被拥有** 的听觉版（与 concept-doc §2.3 Sensation/Submission 对齐）。

推荐风格（程序化可实现的合成美学，非采样流派）：
- **主基调：soft lo-fi / warm ambient pad** —— 暖色正弦/三角振荡器 + 慢起音包络 + 低通柔化 + 算法混响，无硬瞬态。
- **副质感：acoustic-pluck（拟木吉他/八音盒）** —— 三角波 + 快起指数衰减，作为旋律/音效的「有机」音色，制造陪伴感。
- **拒绝**：电子锐利 lead、强 4-on-the-floor 鼓、任何紧张/悬疑音色（伤治愈）。

音色调色板（与 art-bible §3.1 马卡龙色同构，听觉化）：
| 角色 | 听觉映射 | 合成手段 |
|---|---|---|
| 奶白(基底) | 极简铺底 pad、空灵 | 双失谐 sine 长音 + 慢 attack |
| 樱粉(主色) | 温暖主旋律、柔和 | triangle pluck + 轻混响 |
| 薄荷绿(辅·成长/成功) | 升级/解锁的正向闪亮 | bell(正弦+2/3 泛音) 上行 |
| 鹅黄(辅·能量) | 主动加成/收菜的轻快 | 明亮 triangle 短促 sparkle |
| 雾霾蓝(辅·冷静) | 待领取/模态的平和 | 低 sine + 软 whoosh |
| 暖橘(CTA) | 主操作确认 | 圆润 wood-block(sine blip) |
| 莓果红/星金(稀有) | 抽卡 SSR 惊喜峰值 | 多泛音 chime fanfare + shimmer |

### 1.2 主旋律情绪与陪伴感
- **调性**：C 大调（或关系 a 小调的柔和版），五声音阶 + add9/maj7 堆叠，避免导音强解决（防「推进感/紧张感」）。
- **旋律写法**：短句、留白、重复中微变（似「哼唱」），由 triangle pluck 在 pad 上轻奏，像「小动物在旁边哼歌」。
- **节奏**：60–75 BPM；餐厅流略快(≈70)，宿舍流更慢(≈60)。全曲无强拍重音，避免「催促」。

### 1.3 双流经济 → 双 BGM 层（核心建议）
对齐 system-idle-restaurant §2.5 双流：餐厅事件流(主,≈80%) + 宿舍时间流(辅,≈20%)。建议**分场景两套 BGM 层、共享同一和声骨架**，在场景切换时交叉淡入（crossfade 1.5–2s），而非全局单一 BGM。

| 场景/流 | BGM 层 | 情绪曲线 | 配置 |
|---|---|---|---|
| 中枢地图 / HUB（主菜单浮层） | Home 层 | 中性温暖、邀请感 | pad + 稀疏 bell 动机 |
| 餐厅（主事件流, ≈80%） | Restaurant 层 | 「忙但 cozy」的陪伴主舞台：pad + 轻 pulse + 更显的 pluck 旋律 | ≈70 BPM；加一层极轻滤波噪声 pulse（拟环境暖意，非鼓点） |
| 宿舍/撸毛馆（辅时间流, ≈20%） | Dormitory 层 | 放缓、亲密、lullaby 感：去 pulse，加长 pad + 偶发稀疏 bell | ≈60 BPM；更慢 attack，更空 |
| 动才市场/抽卡 | 沿用 Restaurant/Home 层，揭示时短时叠加 shimmer 层 | 平时平稳，**仅在揭示（尤其 SSR/50 保底）出现短促惊喜峰值** | 揭示期间 music duck −6dB，0.8–1.2s 后回弹 |

**情绪曲线总纲**（对齐 art-bible §8「慢起、柔动、峰值短促（惊喜只在抽卡）」）：BGM 全程**无渐强 build**，保持 ambient 稳态；唯一的「峰值」由抽卡揭示的 SFX/shimmer 提供，且峰值后迅速回落，不破坏治愈。

### 1.4 动态混音策略（总线结构）
```
Master (±0dB, 限幅 -1dBTP)
 ├─ MusicBus    (默认 -10dB，gacha 揭示 duck → -16dB)
 │    ├─ padLayer
 │    ├─ pluckLayer (旋律)
 │    └─ pulseLayer (仅餐厅层)
 ├─ SfxBus      (默认 -6dB)
 │    ├─ uiLayer
 │    ├─ feedbackLayer (收菜/上菜/解锁/升级/撸毛)
 │    └─ gachaLayer (揭示/SSR/保底)
 └─ VoBus (预留，本期无 VO；角色声线方向见 §5)
```
- 所有总线经一个轻 master compressor（阈值 −18dB，ratio 2:1）防削波。
- 静音/减弱：音效开关、BGM 开关独立；「减弱动效」(reduce motion) 不强制关音频，但提供独立「音效开关」一键全关（与 art-bible §9 / ux §5 一致）。音频资源字节=0，「关闭」仅停振荡器，不释放任何资产。

## 3. 音频实现策略（关键 · 受 4MB 约束）

### 3.1 方案评估
| 方案 | 说明 | 主包字节 | 契合度 | 风险 |
|---|---|---|---|---|
| **(a) WebAudio 程序化合成** ✅ 推荐主方案 | 振荡器+包络+滤波+算法混响实时合成 BGM 与全部 SFX，零音频文件 | **0** | ★★★★★ 同构零贴图契约、零包体、内容增量不涨包 | 需自研轻量合成/排序引擎；iOS 需用户手势 resume；BGM「真实乐器感」弱于采样 |
| (b) 极小音频文件放分包 | mp3/ogg 采样，主包不放大文件，仅放分包 | 主包 0 / 分包数 KB–数百 KB | ★★★ 省事但破「零资源字节」哲学 | 分包占 16MB 预算；离线首声有加载；与零贴图精神不完全同构 |

### 3.2 推荐可行方案
**主方案 = (a) 100% WebAudio 程序化合成**（BGM + 全部 SFX）。(b) 仅作为**可选增强**：若个别「招牌时刻」（如 SSR 揭示 shimmer、BGM 铺底）确需采样质感，才用极少量压缩采样，且**只进分包、永不进主包**。默认配置 = 全程序化，采样资产 = 0。

技术要点（微信小游戏）：
- **上下文**：`wx.createWebAudioContext()`（微信提供 WebAudio 子集）；若个别机型/基础库不支持，回退到 `wx.createInnerAudioContext()` 播放**分包内**预生成短采样（仅兜底，默认不触发）。
- **自动播放策略**：首个用户手势（`sfx.ui.tap` 首次触发）内 `audioCtx.resume()`；在此之前静音等待，不报错。
- **合成引擎**（计入主包 JS，属现有主包范畴，预计新增 ≤15–20KB）：振荡器工厂（sine/triangle/square 滤波）、ADSR 包络、噪声发生器（撸毛/pulse/whoosh）、反馈延迟混响、轻 master compressor、简易步进排序器（BGM 循环）。
- **性能预算**：复音上限 **≤8 voice** 同时；voice stealing（最旧/最低优先级回收）；每 voice CPU 极低（单振荡器+包络）。内存：无音频资产堆，仅少量 JS 对象，**≈0 资产字节**。

### 3.3 主包 / 分包容量预算（不破 4MB 红线）
- **主包音频资产预算 = 0 字节（硬约束）**：全程序化 → 听觉资产字节=0，与视觉 atlas=0 同构，彻底守住 4MB。
- 合成引擎代码归入主包 JS：当前主包 ≈ **131.5KB（minified，handoff 口径）/ 原始 src+game.js ≈ 228KB**；新增合成/排序模块 ≈ +15–20KB → 主包 ≈ **~150–250KB ≪ 4MB**，余量 ≈ **3.75–3.85MB** 全留给游戏逻辑/其他代码，**音频不占一分主包**。
- **分包（release-plan.md §3.3 命名 `sub-audio`，16MB 总池内）音频预算**：发布侧已为音频预留 `sub-audio` 分包规划，建议上限 **≤2MB**（作为主包外最大增量），加载时机="首次进入需音频的场景 / 设置开启"，并列为 v1.0 **非阻塞项**（可 v1.1 接入，不挡发布门控）。**音频侧实际占用**：默认 100% 程序化 → 主包与 `sub-audio` 均为 **0 字节**；若启用可选 (b) 采样增强，我方建议实际支出 **≤512KB**（单采样 ≤32KB），远低于 ops 预留的 2MB 天花板，余量留动物参数/场景/图鉴。绝不进主包。
- **远程资源域名白名单（art-bible §A.5）**：默认程序化路径无远程音频 → **无需白名单**；仅当 (b) 改为「远程流式采样」时才需微信后台配置，由启用 (b) 的一方于提审前就绪。
- **校验命令（落盘后工程侧核对）**：主包 `du -sh` < 4MB 且主包内 `assets/audio/` 应为空或仅符号链接；真机分包大小核查。

### 3.4 事件命名与接入约定
- **SFX**：`sfx.<category>.<name>`（见 §2 表），与 ux §3.2 `[SFX:xxx]` 占位对齐；工程侧在对应交互点 `play('sfx.xxx')` 即可，音频模块按名查表合成。
- **BGM**：`bgm.<scene>.<layer>`（home / restaurant / dormitory）；场景切换调用 `crossfadeTo('bgm.restaurant')`。
- **参数集中**：所有音色参数集中在音频模块配置（类比 `tunables.js` 的 `TUNED` 段），运行时引用；不写死数值到音频逻辑。

### 3.5 与锁参 / 经济零耦合声明
- 音频模块**只读事件信号**（如 `canPet→DAILY_CAP`、`pity≥50`、`T_ORDER` 结算 tick），**不写回**任何经济/数值；`ACTIVE_BONUS`/`T_CAP`/`offline_factor`/稀有度/四货币 等锁参对音频透明且无修改。
- 音频表现不因稀有度/数值改变而要求改锁参；SSR/50 保底音频仅是「响应该状态」的更亮合成，不反向影响概率/保底。
