# 《可爱小动物餐厅》美术圣经 · v0.3（概念对齐 + 程序化 + 生产清单）

> 文档性质：视觉身份基准（Art Bible v0.3）
> 对齐输入：design-strategist《概念文档》视觉锚点 v1 + 物种谱系/角色数/稀有度规格 v1
> 平台约束：微信小游戏 · Cocos Creator · 主包 ≤4MB · 纯 Canvas/WebGL
> **主理人一致性裁定（v0.3 固化）**：4 档 N/R/SR/SSR 确认；N = 免费基础动物（新手/任务/合成获取），**不进抽卡池**；抽卡付费池 = R/SR/SSR（R60/SR30/SSR10），与 concept-doc.md §7.1 对齐。

**概念对齐声明**：视觉第一性 =「被陪伴的安心感」，落地为五锚点——马卡龙/奶油低饱配色、2–3 头身圆润幼态、扁平+轻软阴影的程序化矢量、温暖松弛无攻击性、参数驱动的程序化 idle。参考对标：治愈 2D 取《动物餐厅》《猫咪和汤》《旅行青蛙》；程序化取《Florence》色块 + 《Alto's Odyssey》渐变天空。

---

## 1. 视觉定位声明
**用圆润治愈的原创小动物 IP，把"开一家温柔的小餐厅"做成可收集、可陪伴、可分享的视觉日常。** 靠程序化矢量低包体实现海量原创形象，靠参数驱动 idle 制造活物感。

---

## 2. 目标受众视觉画像
**人群**：女性向治愈玩家（"她力量"），18–35，泛二次元/插画审美，碎片化休闲，强分享与审美认同。
- **审美偏好**：低饱和高明度奶油感马卡龙配色；圆润有呼吸感的造型；扁平+轻软阴影的手作微厚涂质感；角色会表达情绪（表情包/陪伴来源）。
- **情绪触点**：被治愈｜被陪伴（idle 活物感）｜收集成就感（稀有度梯度+抽卡惊喜）｜分享欲（表情包/姿势/抽卡高光，竖屏友好）。
- **明确避开**：尖锐棱角/纯黑描边/硬阴影｜高饱和荧光撞色｜过度堆萌油腻｜写实毛发/逐张高精贴图。

## 3. 色彩系统
**治愈系逻辑**：暖调为基底，冷调仅平衡；高明度中低饱和；"色块+描边"建立层级，不靠强对比。
### 3.1 调色板
| 角色 | HEX | 用途 |
|---|---|---|
| 奶白（基底） | `#FFF7EF` | 页面/卡面大底 |
| 樱粉（主色） | `#F7D9D2` | 界面背景块、按钮底 |
| 薄荷绿（辅） | `#B8E0CB` | 成长/自然/成功 |
| 鹅黄（辅） | `#FBE3A1` | 能量/温暖点缀 |
| 雾霾蓝（辅） | `#CFE3EC` | 信息区/冷静平衡 |
| 暖橘（CTA） | `#FF9E68` | 主操作按钮、进度 |
| 莓果红（稀有） | `#E8587E` | 稀有度顶/抽卡惊喜 |
| 暖墨（文字） | `#5A4A42` | 正文/标题 |
| 暖棕（描边） | `#8A7268` | 角色/物件统一描边 |
> 马卡龙核心四色 = 奶白/樱粉/薄荷绿/鹅黄。
### 3.2 对比度与可达性
- 暖墨置奶白约 8:1，满足 WCAG **AAA**，作全局文字基准。
- 暖橘配白字约 2.4:1，**禁**用于小字；仅大色块按钮+描边/图标兜底。
- 稀有度/状态**不依赖颜色单编码**（见第 9 节）；暗场景用同套色相降明度版本。

## 4. 角色设计语言（卡牌 + 2D 模型 · 程序化拼装）
**一句话原则**：头身比统一、剪影可辨、身份色绑定、表情会说话；全部由"基础部件 + 配色参数"程序化拼装，用极少基础贴图组合大量原创形象。

### 4.1 形体规范
- **头身比**：2–3 头身（约 1:2~1:3），大头小身、圆润幼态（参数插值，不另存贴图）。
- **五官**：大眼占脸约 1/3，眼内高光 1–2 处；鼻嘴极简；固定半透明暖粉腮红。
- **轮廓**：闭合一笔圆润外轮廓 + 1–2px 暖棕描边。
- **材质**：扁平 + 轻软阴影/微厚涂，优先程序化矢量 + 渐变生成，避免逐张高精位图。

### 4.2 辨识度三策略（须至少满足两条）
1. **剪影可辨**：靠耳/尾/体型差异，关颜色也能认。
2. **身份色绑定**：每只动物分配一个主身份色（来自配色预设 12 套之一），用于卡底与描边同源。
3. **专属配件**：围裙/厨师帽/领结等"职业感"小物。

### 4.3 卡牌立绘 vs 2D 模型分工
- **卡牌立绘**：由部件参数运行期拼装合成静态高精度（含表情/姿势），不预存位图。
- **2D 模型（Spine/Armature）**：店内互动/待机/喂食，骨骼挂接同一套程序化部件切片。
- 立绘与模型共用同一套线稿/配色/参数。

### 4.4 程序化拼装体系（生产清单版）★核心
**设计目标**："极少基础贴图 + 参数组合"产出海量原创小动物，新增动物不新增贴图字节。

**4.4.1 基础部件库（单一 base-parts atlas ≤1024²）**
| 部件 | 槽位 | 家族分配（硬隔离） |
|---|---|---|
| 头 | 6 | 哺乳圆头系×3 / 鸟头×1 / 球头×1 / 鱼头×1 |
| 身 | 5 | 哺乳胖 / 哺乳瘦 / 鸟 / 圆团 / 通用(水族复用圆团+tint) |
| 耳 | 8 | 哺乳 长/圆/尖/垂/折×5 / 鸟冠羽×1 / 圆团芽耳×1 / 水族鳍耳·无×1 |
| 尾 | 6 | 哺乳 长/蓬松/短×3 / 鸟羽尾×1 / 圆团小尾·无×1 / 水族鱼尾×1 |
| 肢 | 3 | 双足(哺乳立姿+鸟共用) / 四足(哺乳) / 短肢·无肢·鳍(圆团+水族) |
| 面部 | 各4–6 | 眼/鼻/嘴/腮红，参数化可组合 |
| 配件 | 8 | 围裙/厨师帽/领结/头巾/眼镜/围脖/小包/碗 |
| 配色预设 | 12 | 哺乳4 / 鸟4 / 圆团4（水族复用圆团4，跨家族不串味） |
| 表情 | 6 | 开心/害羞/撒娇/满足/惊讶/睡着 |
> atlas 校验：头3+1+1+1=6 ✓；耳5+1+1+1=8 ✓；尾3+1+1+1=6 ✓；身5 ✓；肢3 ✓。**无需扩 atlas**。

**4.4.2 单只动物贴图预算**
- **单只动物 = 0 张独立贴图**，仅引用 base-parts atlas。
- 新增一只动物 = 新增一组参数（~32–64 字节 JSON：partsId + colorPresetId + 表情Id + 形变参数），贴图字节零增长。
- 组合空间 ≈5.2 万种 ≫ 所需；角色采用**策展式固定参数组**（非穷举），无需为角色数量扩 atlas。

**4.4.3 程序化拼装规则（5 条 + 硬护栏）**
1. **分层 z 序**：身体层(身+肢) → 头部层(头+耳+尾+面部) → 配件层。
2. **配色预设**：身份色作用于主填充，描边色统一暖棕或同源加深；每家族绑定 4 套预设，跨家族不串味。
3. **形变插值**：头身比在 2–3 头身间参数插值。
4. **一致性约束**：所有部件共享描边权重/阴影方向/圆角语言，防 uncanny 拼接。
5. **稀有度叠加**：SSR 仅允许在对应家族「高光部件/特效光环」叠加，**不得改变剪影家族**（SSR 兔仍是兔，不长鱼尾）。
- **★硬护栏（来自 design-strategist）**：每只动物严格归属唯一家族；仅可用该家族的头/身/耳/尾/肢子集；**跨家族组合禁止**（如 鱼头+猫耳+羽尾 不可）；同家族内任意组合允许。

**4.4.4 家族允许组合矩阵**
| 家族 | 可用头 | 可用耳 | 可用尾 | 可用肢 | 配色预设 | 引入阶段 |
|---|---|---|---|---|---|---|
| 哺乳 | 圆头系×3 | 长/圆/尖/垂/折×5 | 长/蓬松/短×3 | 双足立姿·四足 | 4 套 | 首发(主力) |
| 鸟类 | 鸟头×1 | 冠羽×1(无外耳) | 羽尾×1 | 双足 | 4 套 | 首发 |
| 圆团 | 球头×1 | 芽耳×1(可选无) | 小尾/无×1 | 短肢/无肢 | 4 套 | 首发 |
| 水族 | 鱼头×1 | 鳍耳/无×1 | 鱼尾×1 | 鳍(复用短肢槽) | 复用圆团4套 | 长线(首个大版本) |

## 5. 环境与餐厅美术基调
**场景三层级**（圆角 + 统一描边 + 暖光，参考《动物餐厅》店态与《Alto's Odyssey》渐变天空）：
| 层级 | 内容 | 基调 |
|---|---|---|
| 店外 | 小屋外观、招牌、绿植、柔和渐变天光 | 邀请感 |
| 店内 | 就餐区、圆角桌椅、布艺/木质、暖吊灯 | 陪伴主舞台 |
| 厨房（后台） | 圆角厨具、秩序货架、冷调微降明 | 经营反馈区 |
- 物件全圆角（半径 ≥12%），描边同源暖棕，扁平+轻软阴影。
- 光影：暖色环境光、柔和高光、**禁**硬投影；阴影为半透明暖灰贴地椭圆；天/背景用程序化渐变。
- 景深：1–2 层视差（平涂色块/渐变而非贴图）。

## 6. 字体与 UI 视觉语气
- 标题/品牌字：圆体或轻手写圆体（站酷快乐体/系统圆体/得意黑圆体），字间距 +2~4%。
- 正文/数字：清晰圆体或无衬线（≤20px 小字避纯手写）。
- 字号层级（基准 750×1334）：H1 40–44px｜H2 30–32px｜Body 22–24px｜Caption 18–20px｜Num 24–28px。
- 字重：常规/中粗两档，禁极细(<300)与极粗(>800)。
- 字色：暖墨为主；强调数字可用暖橘但需描边兜底。

## 7. 图标 / 卡片框体规范
### 7.1 卡片框
圆角矩形（圆角 28–32px），双层描边；顶部稀有度色条（占卡高 6–8%）；立绘区(≥60%)+名签/属性区；同一套圆角/描边，仅以稀有度色+角标+纹理区分。
### 7.2 稀有度配色（双编码：颜色 + 图标/纹理，色盲安全）
| 稀有度 | 主色 HEX | 角标形状 | 纹理/演出 |
|---|---|---|---|
| N | `#A8C0B0` 灰绿 | 圆点 | 无 |
| R | `#8FB8E0` 蓝 | 单钻 | 轻光 |
| SR | `#C9A6E8` 紫 | 双钻 | 边框微光 |
| SSR | `#F4C95D` 金 | 星冠 | 流光 + 粒子 + 全屏彩带 |
> **主理人一致性裁定（v0.3 固化）**：4 档 N/R/SR/SSR 已确认；**N = 免费基础动物（新手/任务/合成获取），不进抽卡池**；抽卡付费池为 R/SR/SSR（R60/SR30/SSR10），与 concept-doc.md §7.1 对齐。
> **护栏**：身份色（角色填充，来自 12 配色预设）与稀有度色（卡框条/角标）分属不同 UI 层，避免撞色（如蓝身份鸟 + 蓝 R 条时以角标形状区分）。
### 7.3 图标网格
基准 24/48/96（2x 48/192），圆角 20%，内边距 2px；线面统一；功能图标暖墨描边，资源图标对应辅色填充。

## 8. 动画与表现基调
**节奏总纲**：慢起、柔动、峰值短促（惊喜只在抽卡）。**全部 idle/互动为参数驱动程序化动画（骨骼/正弦插值，无逐帧序列）**。
### 8.1 待机（程序化 idle）
呼吸（scale 1.00↔1.03，2.0s 正弦）｜眨眼（每 3–5s，50–80ms）｜微摆（耳/尾 ±3° 错相位）。Spine 骨骼挂接程序化部件或 Cocos tween 驱动，**无逐帧 PNG 序列**。
### 8.2 互动反馈
点击：弹跳（1.0→1.12→1.0，120ms）+ 爱心/星星粒子 3–5 颗。喂食：咀嚼 2 次 + 满足表情 + 头顶"+1"。
### 8.3 抽卡演出（惊喜峰值，竖屏友好）
卡背翻转(0.3s)→光效炸开(0.2s)→角色登场定格(0.4s)；SSR 叠加全屏彩带/星屑+边框流光(1.2–1.5s，可跳过)；十连逐张 0.15s 错位翻出，末张 SSR 触发高潮。
### 8.4 表情系统
6 基础表情（眉+眼+嘴部件组合切换），复用同一套脸部件，便于表情包/分享图。

## 9. 可访问性分级
**建议级别：Standard 为全量基准，关键路径达 Comprehensive。**
| 级别 | 要点 | 本项目落地 |
|---|---|---|
| **Basic** | 文本可缩放、基础对比度 | 暖墨文字 8:1；正文下限 18px |
| **Standard**（基准） | 色盲友好、字幕、输入可重映射 | 稀有度颜色+形状双编码；动效开关；按钮≥44px 热区 |
| **Comprehensive**（关键路径） | 高对比模式、reduce motion、文本 1.0–1.5x、色盲模拟 | "高对比 UI 皮肤"；全局动效一键减弱；稀有度额外纹理编码 |
**要点**：稀有度绝不只靠颜色；正文 ≥18px；reduce motion 关呼吸/粒子/炸裂保留静态定帧；可点元素 ≥44×44 设计像素。

## 附录 A · 资产规格（生产清单版 · 呼应 4MB 主包限制）

### A.1 推荐尺寸与格式
| 资产类型 | 推荐尺寸 | 格式/压缩 | 备注 |
|---|---|---|---|
| **基础部件图集** | ≤1024×1024 | PNG-8/WebP + ASTC | 角色唯一贴图来源 |
| 角色立绘/模型 | 运行时合成 | 由 base-parts atlas 拼装 | 0 独立贴图 |
| UI 图标 | 96/192（2x） | PNG-8/WebP | 统一进 UI 大图集 |
| 场景背景 | 2048² 或分块 1024 | ASTC 6×6 + 程序化渐变 | 分层平涂/渐变 |
| 表情包/分享图 | 750/1080² | PNG | 运行期合成，不进首包 |

### A.2 程序化生成方案（运行时）
Cocos 端按角色参数从 base-parts atlas 切片拼装，**着色器 tint/渐变上色**合成立绘与 Spine 装配。**需与程基岩核对**：着色器上色（顶点色/tint vs 自定义 shader）、ASTC/PVRTC 机型回退、Spine 运行时与 Cocos 插件版本对齐。

### A.3 Spine 预算
单角色骨骼 ≤30 根；图集即 base-parts atlas（≤1024²）；动画 ≤8 个/角色。首包仅内置 1–2 只 mascot 参数+Spine；其余动物=参数走分包。

### A.4 分包策略——4MB 只放"能玩的最小集"
- **首包（≤4MB）**：核心 UI 骨架 + 字体子集 + 1 张店外/店内缩略背景 + **base-parts atlas** + 首只动物参数与 Spine + 抽卡演出必需特效。
- **分包按需加载**：其余动物=参数组（极小）、完整场景、图鉴、音效、表情包，按"首次进入模块"动态加载。
- **包体收益**：角色=参数而非贴图，首发 36 → 图鉴 60–80 → 水族 +8~10，**数量增长几乎不挤压 4MB 主包**。

### A.5 与引擎/管线风险（待程基岩核对）
着色器 tint 方案与机型兼容回退；Spine 版本对齐防首包膨胀；远程资源域名白名单需微信后台提前配置。

### A.6 美术生产清单（来自 design-strategist 规格，供排期与预载）
**A.6.1 角色数**

- 水族家族首个大版本引入 **+8~10 只**（复用圆团身 + 鱼头/鳍耳/鱼尾，不扩 atlas）。

**A.6.2 首发 36 只家族×稀有度矩阵（图鉴占比，独立于出率）**
