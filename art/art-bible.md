## 1. 视觉定位声明
**用圆润治愈的原创小动物 IP，把"开一家温柔的小餐厅"做成可收集、可陪伴、可分享的视觉日常。** 靠程序化矢量低包体实现海量原创形象，靠参数驱动 idle 制造活物感。

---

## 2. 目标受众视觉画像
**人群**：女性向治愈玩家（"她力量"），18–35，泛二次元/插画审美，碎片化休闲，强分享与审美认同。
- **审美偏好**：低饱和高明度奶油感马卡龙配色；圆润有呼吸感的造型；扁平+轻软阴影的手作微厚涂质感；角色会表达情绪（表情包/陪伴来源）。
- **情绪触点**：被治愈｜被陪伴（idle 活物感）｜收集成就感（稀有度梯度+抽卡惊喜）｜分享欲（表情包/姿势/抽卡高光，竖屏友好）。
- **明确避开**：尖锐棱角/纯黑描边/硬阴影｜高饱和荧光撞色｜过度堆萌油腻｜写实毛发/逐张高精贴图。

## 3. 色彩系统
**治愈系逻辑**：暖调为基底，冷调仅平衡；高明度中低饱和；"色块+描边"建立层级，不靠强对比。

|---|---|---|

| 薄荷绿（辅） | `#B8E0CB` | 成长/自然/成功 |

- 暖墨置奶白约 8:1，满足 WCAG **AAA**，作全局文字基准。

- 稀有度/状态**不依赖颜色单编码**（见第 9 节）；暗场景用同套色相降明度版本。

## 4. 角色设计语言（卡牌 + 2D 模型 · 程序化拼装）
**一句话原则**：头身比统一、剪影可辨、身份色绑定、表情会说话；全部由"基础部件 + 配色参数"程序化拼装，用极少基础贴图组合大量原创形象。

### 4.1 形体规范
- **头身比**：2–3 头身（约 1:2~1:3），大头小身、圆润幼态（参数插值，不另存贴图）。
- **五官**：大眼占脸约 1/3，眼内高光 1–2 处；鼻嘴极简；固定半透明暖粉腮红。
- **轮廓**：闭合一笔圆润外轮廓 + 1–2px 暖棕描边。
- **材质**：扁平 + 轻软阴影/微厚涂，优先程序化矢量 + 渐变生成，避免逐张高精位图。

### 4.2 辨识度三策略（须至少满足两条）
1. **剪影可辨**：靠耳/尾/体型差异，关颜色也能认。
2. **身份色绑定**：每只动物分配一个主身份色（来自配色预设 12 套之一），用于卡底与描边同源。
3. **专属配件**：围裙/厨师帽/领结等"职业感"小物。

### 4.3 卡牌立绘 vs 2D 模型分工
- **卡牌立绘**：由部件参数运行期拼装合成静态高精度（含表情/姿势），不预存位图（canvas2d 绘制，无位图）。
- **2D 模型（canvas2d 参数化绘制）**：店内互动/待机/喂食，参数化绘制同一套程序化部件（无骨骼、无 Spine）。
- 立绘与模型共用同一套线稿/配色/参数。

### 4.4 程序化拼装体系（生产清单版）★核心
**设计目标**："极少基础贴图 + 参数组合"产出海量原创小动物，新增动物不新增贴图字节。

**4.4.1 基础部件库（程序化部件绘制函数库，无位图，atlas 字节=0）**
| 部件 | 槽位 | 家族分配（硬隔离） |
|---|---|---|
| 头 | 6 | 哺乳圆头系×3 / 鸟头×1 / 球头×1 / 鱼头×1 |
| 身 | 5 | 哺乳胖 / 哺乳瘦 / 鸟 / 圆团 / 通用(水族复用圆团+参数化填色) |
| 耳 | 8 | 哺乳 长/圆/尖/垂/折×5 / 鸟冠羽×1 / 圆团芽耳×1 / 水族鳍耳·无×1 |
| 尾 | 6 | 哺乳 长/蓬松/短×3 / 鸟羽尾×1 / 圆团小尾·无×1 / 水族鱼尾×1 |
| 肢 | 3 | 双足(哺乳立姿+鸟共用) / 四足(哺乳) / 短肢·无肢·鳍(圆团+水族) |
| 面部 | 各4–6 | 眼/鼻/嘴/腮红，参数化可组合 |
| 配件 | 8 | 围裙/厨师帽/领结/头巾/眼镜/围脖/小包/碗 |
| 配色预设 | 12 | 哺乳4 / 鸟4 / 圆团4（水族复用圆团4，跨家族不串味） |
| 表情 | 6 | 开心/害羞/撒娇/满足/惊讶/睡着 |
> atlas 校验：头3+1+1+1=6 ✓；耳5+1+1+1=8 ✓；尾3+1+1+1=6 ✓；身5 ✓；肢3 ✓。**无需扩 atlas**。

**4.4.2 单只动物贴图预算**
- **单只动物 = 0 张独立贴图**，仅引用**程序化部件绘制函数库**（canvas2d 矢量原语 + JSON 参数，atlas 字节=0，不变量#1）。
- 新增一只动物 = 新增一组参数（~11–64 字节 JSON：partsId + colorPresetId + 表情Id + 形变参数，新手 N 动物部件少≈11B/只，见 asset-spec §2.4/§0），贴图字节零增长。
- 组合空间 ≈5.2 万种 ≫ 所需；角色采用**策展式固定参数组**（非穷举），无需为角色数量扩 atlas。

**4.4.3 程序化拼装规则（5 条 + 硬护栏）**
1. **分层 z 序**：身体层(身+肢) → 头部层(头+耳+尾+面部) → 配件层。
2. **配色预设**：身份色作用于主填充，描边色统一暖棕或同源加深；每家族绑定 4 套预设，跨家族不串味。
3. **形变插值**：头身比在 2–3 头身间参数插值。
4. **一致性约束**：所有部件共享描边权重/阴影方向/圆角语言，防 uncanny 拼接。
5. **稀有度叠加**：SSR 仅允许在对应家族「高光部件/特效光环」叠加，**不得改变剪影家族**（SSR 兔仍是兔，不长鱼尾）。
- **★硬护栏（来自 design-strategist）**：每只动物严格归属唯一家族；仅可用该家族的头/身/耳/尾/肢子集；**跨家族组合禁止**（如 鱼头+猫耳+羽尾 不可）；同家族内任意组合允许。

**4.4.4 家族允许组合矩阵**
| 家族 | 可用头 | 可用耳 | 可用尾 | 可用肢 | 配色预设 | 引入阶段 |
|---|---|---|---|---|---|---|
| 哺乳 | 圆头系×3 | 长/圆/尖/垂/折×5 | 长/蓬松/短×3 | 双足立姿·四足 | 4 套 | 首发(主力) |
| 鸟类 | 鸟头×1 | 冠羽×1(无外耳) | 羽尾×1 | 双足 | 4 套 | 首发 |
| 圆团 | 球头×1 | 芽耳×1(可选无) | 小尾/无×1 | 短肢/无肢 | 4 套 | 首发 |
| 水族 | 鱼头×1 | 鳍耳/无×1 | 鱼尾×1 | 鳍(复用短肢槽) | 复用圆团4套 | 长线(首个大版本) |

## 5. 环境与餐厅美术基调
**场景三层级**（圆角 + 统一描边 + 暖光，参考《动物餐厅》店态与《Alto's Odyssey》渐变天空）：
| 层级 | 内容 | 基调 |
|---|---|---|
| 店外 | 小屋外观、招牌、绿植、柔和渐变天光 | 邀请感 |
| 店内 | 就餐区、圆角桌椅、布艺/木质、暖吊灯 | 陪伴主舞台 |
| 厨房（后台） | 圆角厨具、秩序货架、冷调微降明 | 经营反馈区 |
- 物件全圆角（半径 ≥12%），描边同源暖棕，扁平+轻软阴影。
- 光影：暖色环境光、柔和高光、**禁**硬投影；阴影为半透明暖灰贴地椭圆；天/背景用程序化渐变。
- 景深：1–2 层视差（平涂色块/渐变而非贴图）。

## 6. 字体与 UI 视觉语气
- 标题/品牌字：圆体或轻手写圆体（站酷快乐体/系统圆体/得意黑圆体），字间距 +2~4%。
- 正文/数字：清晰圆体或无衬线（≤20px 小字避纯手写）。
- 字号层级（基准 750×1334）：H1 40–44px｜H2 30–32px｜Body 22–24px｜Caption 18–20px｜Num 24–28px。
- 字重：常规/中粗两档，禁极细(<300)与极粗(>800)。
- 字色：暖墨为主；强调数字可用暖橘但需描边兜底。

## 7. 图标 / 卡片框体规范
### 7.1 卡片框
圆角矩形（圆角 28–32px），双层描边；顶部稀有度色条（占卡高 6–8%）；立绘区(≥60%)+名签/属性区；同一套圆角/描边，仅以稀有度色+角标+纹理区分。
### 7.2 稀有度配色（双编码：颜色 + 图标/纹理，色盲安全）
| 稀有度 | 主色 HEX | 角标形状 | 纹理/演出 |
|---|---|---|---|
| N | `#A8C0B0` 灰绿 | 圆点 | 无 |
| R | `#8FB8E0` 蓝 | 单钻 | 轻光 |
| SR | `#C9A6E8` 紫 | 双钻 | 边框微光 |
| SSR | `#F4C95D` 金 | 星冠 | 流光 + 粒子 + 全屏彩带 |
> **主理人一致性裁定（v0.3 固化）**：4 档 N/R/SR/SSR 已确认；**N = 免费基础动物（新手/任务/合成获取），不进抽卡池**；抽卡付费池为 R/SR/SSR（R60/SR30/SSR10），与 concept-doc.md §7.1 对齐。
> **护栏**：身份色（角色填充，来自 12 配色预设）与稀有度色（卡框条/角标）分属不同 UI 层，避免撞色（如蓝身份鸟 + 蓝 R 条时以角标形状区分）。
### 7.3 图标网格
基准 24/48/96（2x 48/192），圆角 20%，内边距 2px；线面统一；功能图标暖墨描边，资源图标对应辅色填充。

## 8. 动画与表现基调
**节奏总纲**：慢起、柔动、峰值短促（惊喜只在抽卡）。**全部 idle/互动为参数驱动程序化动画（骨骼/正弦插值，无逐帧序列）**。
### 8.1 待机（程序化 idle）
呼吸（scale 1.00↔1.03，2.0s 正弦）｜眨眼（每 3–5s，50–80ms）｜微摆（耳/尾 ±3° 错相位）。**canvas2d 参数化绘制 + 正弦插值驱动（无骨骼、无 Cocos tween）**，**无逐帧 PNG 序列**。
### 8.2 互动反馈
点击：弹跳（1.0→1.12→1.0，120ms）+ 爱心/星星粒子 3–5 颗。喂食：咀嚼 2 次 + 满足表情 + 头顶"+1"。
### 8.3 抽卡演出（惊喜峰值，竖屏友好）
卡背翻转(0.3s)→光效炸开(0.2s)→角色登场定格(0.4s)；SSR 叠加全屏彩带/星屑+边框流光(1.2–1.5s，可跳过)；十连逐张 0.15s 错位翻出，末张 SSR 触发高潮。
### 8.4 表情系统
6 基础表情（眉+眼+嘴部件组合切换），复用同一套脸部件，便于表情包/分享图。

## 9. 可访问性分级
**建议级别：Standard 为全量基准，关键路径达 Comprehensive。**
| 级别 | 要点 | 本项目落地 |
|---|---|---|
| **Basic** | 文本可缩放、基础对比度 | 暖墨文字 8:1；正文下限 18px |
| **Standard**（基准） | 色盲友好、字幕、输入可重映射 | 稀有度颜色+形状双编码；动效开关；按钮≥44px 热区 |
| **Comprehensive**（关键路径） | 高对比模式、reduce motion、文本 1.0–1.5x、色盲模拟 | "高对比 UI 皮肤"；全局动效一键减弱；稀有度额外纹理编码 |
**要点**：稀有度绝不只靠颜色；正文 ≥18px；reduce motion 关呼吸/粒子/炸裂保留静态定帧；可点元素 ≥44×44 设计像素。

### 10.1 关键约束交底：把「星露谷 cozy」翻译进零贴图管线

星露谷（Stardew Valley）的魅力 = **暖色有限调色板 + 手绘像素 tile + 柔光 + cozy 杂货感**；其本质是**位图像素美术**。本管线**禁止位图**（4MB 主包硬限 + 不变量 #1 atlas 不增长 + 不变量 #2 家族隔离），故必须用**程序化 canvas2d 图元**重建 cozy 身份：

| # | cozy 视觉身份要素（全用 canvas2d 图元实现） | 落地手段 |
|---|---|---|
| 1 | 暖色有限调色板 | §10.3 提案；复用 §3.1 马卡龙核心四色 |
| 2 | 圆润柔和形状 | `roundRect` / `circle` / `ellipse` 组合描出 tile、家具、建筑、动物（R5 契约仅支持此六类 op，无 `arc`/`path`/`bezier`；平滑曲线以 `circle`/`ellipse` 近似） |
| 3 | 简洁描边 | 统一 1–2px 暖棕 `#8A7268`（与 §3/§4 一致） |
| 4 | 动物/建筑形状语言 | 动物复用 §4.4.1 部件词汇；建筑新增一组「建筑图元」（§10.7） |
| 5 | 轻量运动（绘制动画而非 sprite sheet） | sine 呼吸/飘动/昼夜渐变、参数插值，无逐帧 PNG |

**放弃的（Given up，正面交底）：**
- 真实像素纹理 / 抖动（dithering）、逐像素手绘细节；
- 位图植被/光影/云朵、sprite sheet、Perlin 噪声贴图、任何预渲染位图；
- 真·星露谷「像素 art」观感本身。

**获得的（Gained，正面交底）：**
- **atlas 永不增长**（体积恒定，4MB 主包无忧）—— 不变量 #1 天然成立；
- **参数化无限变体**（1 组形状 → N 只动物 / N 块地砖 / N 种家具），零贴图字节；
- **分辨率无关**（任意 DPR 清晰，_retina_ 不糊）；
- **运行时重着色 / 换肤**（同一形状换参数即得新角色/新区域氛围）；
- **动画全数学插值**（无帧图，idle/飘动/抽卡演出皆程序化）；
- **家族隔离由参数强制**（动物部件仅同家族组合，不变量 #2 天然满足）。

**不变量重申**：#1 atlas 永不增长（不新增任何位图，建筑图元亦为参数化路径，可并入白模）；#2 家族硬隔离（沿用 §4.4.3 护栏 + §4.4.4 矩阵；地图建筑无家族概念，动物部件永不跨家族）。

### 10.2 可达观感定位（最接近星露谷的程序化观感）

- **不是真像素 art，是「绘本矢量 cozy」**：取星露谷的暖色 + 圆角软 tile + 柔光描边，用**扁平矢量 + 软渐变阴影 + 轻描边**呈现。参考观感锚点：Alto's Odyssey 渐变天空 + Florence 色块 + Ooblets/cozy 游戏的圆角矢量感（**非像素**）。
- **用「大格子低分辨率矢量」模拟 chunky cozy 感**：tile 用大圆角方格（非真像素），整体低密度、留白、暖；避免堆细节（契合 §2「明确避开：过度堆萌油腻」）。
- **光影**：暖色环境光 + 半透明暖灰贴地椭圆阴影（**无硬投影**）；天/背景程序化渐变；1–2 层视差（平涂色块/渐变，非贴图）。与 §5 环境基调（圆角 + 统一描边 + 暖光）一致。
- **do NOT 提议导入图片**：所有观感均来自 canvas2d 图元 + 渐变 + 参数，无任何位图素材。

### 10.8 与 §8 动画基调、§9 可达性对齐

- **动画基调（§8）**：地图/室内环境动效极慢（云/草/光）；动物 idle 呼吸/眨眼（§8.1）；抽卡峰值惊喜**仅在**动才市场（§8.3）；遵循「慢起、柔动、峰值短促（惊喜只在抽卡）」。
- **Reduce motion（§9 Comprehensive）**：关云移/草摆/呼吸/粒子，保留**静态定帧**（地图静态 + 室内静态 + 动物静止 idle 定帧）。
- **色盲安全（§9 Standard）**：区域 accent 不编码状态；岗位/稀有度仍用形状+图标双编码（§7.2、UX §5）。
- **命中区 ≥44×44（§9）**：地图节点 / 室内可点元素达标。
- **文字 ≥18px、暖墨 8:1（§3.2/§9）**：任意区域维持。

## 附录 A · 资产规格（生产清单版 · 呼应 4MB 主包限制）

> ⚠️ **修订：2026-07-29 正式 pivot 离 Cocos，以微信原生 canvas2d 程序化零贴图为准（用户 OP1-A）**。本附录原「Cocos + base-parts PNG/WebP atlas + Spine 骨骼 + ASTC/ETC2 着色器 tint」表述已全数改写为「微信原生 canvas2d 程序化部件绘制函数库 + JS 运行时填色」，atlas 字节=0（不变量#1），家族硬隔离在绘制调用层生效（不变量#2）。

### A.1 推荐尺寸与格式（零贴图，canvas2d 程序化绘制）
| 资产类型 | 推荐尺寸 | 格式/绘制 | 备注 |
|---|---|---|---|
| **程序化部件绘制函数库** | canvas2d 矢量原语 + JSON 参数 | 运行时 `ctx` 路径绘制（无位图） | 角色唯一绘制来源（atlas 字节=0，不变量#1） |

### A.2 程序化生成方案（运行时，微信原生 canvas2d）
微信原生 canvas2d 按角色参数调用**程序化部件绘制函数**，经 **JS 运行时 `fillStyle`/`strokeStyle` + 渐变**填色/上色合成立绘与 idle 动效（无 Spine、无 Cocos）。**需与 engineering-lead 核对**：JS 运行时填色（fillStyle/strokeStyle + createLinear/RadialGradient）、低色域降级、绘制库组织（无 Spine/Cocos）。

### A.3 动效预算（无骨骼，canvas2d 参数化）
无骨骼（Spine 已弃用）；动画为 **canvas2d 参数化正弦 idle**（呼吸/眨眼/耳尾微摆，§8.1），状态 ≤8 个/角色。首包仅内置 1–2 只 mascot 参数（绘制函数库本就含于主包 JS）；其余动物=参数走分包。

### A.4 分包策略——4MB 只放"能玩的最小集"
- **首包（≤4MB）**：核心 UI 骨架（微信原生 canvas2d 绘制库）+ 字体子集 + 程序化背景参数（无位图）+ 首只动物参数 + 抽卡演出必需 VFX（程序化粒子，无位图）。
- **分包按需加载**：其余动物=参数组（极小，无位图）、完整场景、图鉴、音效、表情包，按"首次进入模块"动态加载。
- **包体收益**：角色=参数而非贴图，首发 36 → 图鉴 60–80 → 水族 +8~10，**数量增长几乎不挤压 4MB 主包**（零贴图下 atlas 字节恒=0）。

### A.5 与引擎/管线风险（待 engineering-lead 核对）
JS 运行时填色 + 低色域降级（替代原着色器 tint）；绘制库极轻量防首包膨胀（Spine 已弃用，无骨骼字节）；远程资源域名白名单需微信后台提前配置。
